# 架构与目录约定

[中文](architecture.md) | [English](architecture.en.md)

本文定义资料组织边界。各产品在自身目录记录实际选型和开放范围。OpenAerial 150 采用市售 MicoAir743 飞控与成品电调；电调具体型号、固件、中间件、计算平台、传感器和算法尚待明确。

## 产品边界

一个产品目录描述一套可以独立理解、搭建和验证的系统。机械结构、电子硬件、整机 BOM、固件、软件、配置、仿真与操作文档共同构成它的复现资料。

产品目录中的 `release.yaml` 用于记录一次发布经过确认的软硬件组合。当前文件是草稿模板。

## 公共模块边界

满足多个产品的实际需求、接口可以独立说明的自研模块，才提取到 `shared/`。产品应记录依赖的准确版本、必要配置及适配关系。

上游项目优先通过来源地址、固定版本或提交号与本地补丁引用；修改后的内容需要说明与上游的差异。

## 配置与产品换代

同一产品的可选配置放入其 `configs/<configuration-id>/`，同时记录对应 BOM、软件与验证结果。目前尚未定义任何配置。

当结构、接口或装配方式发生较大变化时，再评估是否需要独立产品目录。机械与电路修订号、软件版本及整机发布版本分别记录。

## 资料流转

设计源文件 → 导出与制造资料 → BOM 与装配 → 部署与标定 → 仿真或实机验证 → 固定版本发布。

每次变更应核对这条流程中的受影响资料，保留来源和版本关系。

## 市售模块与自研硬件

市售模块在产品 `electronics/` 中记录选型、来源、安装、供电、接线与适配验证。原厂设计资料按实际公开范围引用。

自研板卡在实际开展设计时建立 `source/` 和 `fabrication/`。整机复现资料需要明确哪些内容由本项目设计开放，哪些内容来自外部模块及其官方资料。

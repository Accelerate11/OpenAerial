# 产品发布流程

[中文](releases.md) | [English](releases.en.md)

本仓库尚无产品发布。以下流程用于后续发布可复现的产品组合。

## 发布前准备

1. 核对产品 README 中的规格、成熟度和已验证能力。
2. 固定机械、电路与整机 BOM 修订，核对设计源文件和导出文件一致。
3. 固定配置、固件、软件、训练与仿真所需依赖。
4. 补齐装配、标定、部署、操作和故障排查说明。
5. 完成对应验证，在产品 `tests/` 中给出精简报告或报告索引。
6. 确认许可、来源与署名；检查大型资源的地址、版本和 SHA-256。
7. 填写产品 `release.yaml` 并整理 `CHANGELOG.md`。

尚未完成的验证应在发布说明中明确列出。

## 版本命名

建议整机发布标签使用 `<product-id>/v<version>`。例如 `openaerial-150/v0.1.0` 仅为未来标签示例，当前没有创建该版本。

机械修订、电路修订和软件版本分别维护，通过整机发布清单说明配套关系。历史文件通过 Git 提交与标签保留。

## 发布清单字段

- `schema_version`：本清单格式的版本，当前为 1。
- `product`：稳定产品标识与展示名称。
- `release`：发布版本、状态、日期与准确来源引用；来源使用发布标签或固定提交。
- `hardware`：机械修订、自研板卡修订、市售模块与整机 BOM 的产品内相对路径。`purchased_modules` 记录模块标识、用途、厂商、型号、硬件修订、数量、来源和集成文档路径。
- `configurations`：实际支持的配置，逐项记录标识、目录与适用修订。
- `dependencies`：第三方或公共模块的名称、来源、固定版本及本地补丁。
- `artifacts`：设计导出、固件、权重等交付物的名称、位置、SHA-256 与许可。
- `validation`：验证状态与报告引用。

草稿允许空值；发布前应逐项填写，未采用的模块明确说明不适用。产品清单中的本地路径以该产品目录为基准。

## 发布交付物

按实际需要打包设计文件、制造资料、固件与其他交付物，并为外部文件提供校验信息。发布说明应写清适用配置、验证范围与已知限制。
